# 五七五 — 川柳ゲーム 仕様書 v0.4

作成 2026-08-06 / 更新 2026-08-07

---

## 1. 概要

配られた札を組み合わせて五・七・五の川柳を作り、その出来を人間が判定して競うパーティーゲーム。

札は「5音の札」と「7音の札」の2種類だけ。5音札は**上の句にも下の句にも使える**（順不同）ので、同じ手札でも並べ替えで意味がまったく変わる。ここがこのゲームの中心的な面白さになる。

- ジャンルは**川柳**（季語不要・口語OK・人間や日常を笑うもの）とする。俳句ではないので、季語や切れ字のルールは課さない。
- 勝敗は数値計算ではなく**人間の主観**で決まる。アプリはあくまで札の配布・提出・集計を担当する。

### 想定プレイ人数
- 独断と偏見モード: 3〜8人（親1人 + 詠み手2人以上）
- コンテストモード: 3〜8人（提出者1人 + 採点者2人以上）

---

## 2. 用語

| 用語 | 意味 |
|---|---|
| 5音札 | 5モーラの句が書かれた札。上の句・下の句のどちらにも使える |
| 7音札 | 7モーラの句が書かれた札。中の句にのみ使える |
| 手札 | 各プレイヤーが持つ札。初期は5音札4枚 + 7音札2枚の計6枚 |
| 句（提出句） | 5音札2枚 + 7音札1枚 = 計3枚で構成した五・七・五 |
| 捨て場 | 交換で出した札が表向きに置かれる公開エリア |
| 山札 | 未配布の札の束。5音山と7音山を別々に持つ |
| ラウンド | 1人分の親番／提出番。全員が1周したらゲーム終了 |

---

## 3. 札とカードDB

### 3.1 モーラ（音数）の数え方

かなの文字数ではなく**モーラ数**で数える。

- 拗音（ゃ・ゅ・ょ・ぁ・ぃ・ぅ・ぇ・ぉ）は直前のかなと合わせて **1モーラ**
- 促音（っ）、撥音（ん）、長音（ー）は **1モーラとして数える**

例: 「残業日（ざんぎょうび）」= ざ / ん / ぎょ / う / び = **5モーラ**

カードデータは `reading`（ひらがな読み）を必ず持ち、モーラ数はここから機械的に検証する。

### 3.2 カードデータ構造

```jsonc
{
  "id": "m5-001",          // 一意ID。m5- = 5音札, m7- = 7音札
  "mora": 5,               // 5 | 7
  "text": "残業日",         // 表示テキスト（漢字かな交じり）
  "reading": "ざんぎょうび", // ひらがな読み。モーラ検証に使用
  "tags": ["仕事", "現代"]   // 将来のデッキ切り替え用（v0.1では未使用）
}
```

### 3.2.1 品詞のルール（重要）

**5音札は必ず名詞または名詞句にする。** 助詞で終わってはいけない。

5音札は上の句にも下の句にも置けるのがこのゲームの根幹だが、「妻の目が」「有給を」のように助詞で終わる札は上の句にしか置けず、下句に回した瞬間に句として成立しなくなる。名詞句なら体言止めとして下句に置けるし、上句に置いても後ろに七音が続くので自然に読める。つまり**名詞句にしないと順不同という前提そのものが壊れる**。

- ○「残業日」「上司の目」「据え膳」「ガチャの沼」
- ×「残業日に」「上司の目が」「据え膳を」「ガチャの沼で」

**例外: 慣用句化した表現は5音札に置ける。** 「知らんけど」「草生える」「ととのった」「詰んでいる」のように、語形としては述語でも一語の決まり文句として機能する表現は、体言止めの位置に置いても句が閉じる。「ありがとう」が文法上は形容詞の連用形でも実質ひとつの語であるのと同じ扱い。データ上は `"idiom": true` を立てて品詞チェックを免除する。

一方、「炎上し」「検索し」のような単なる連用中止形はこれに当たらない。単独で切れる決まり文句になっているかどうかが基準。

**7音札（中の句）はこの制限を受けない。** むしろ述語句・接続の形（「〜して」「〜だった」「〜が消えた」）のほうが上下の句をつなぐので望ましい。

このルールは検証スクリプトで機械的にチェックする（3.4参照）。

### 3.3 デッキ

札は**デッキ単位**で管理し、ゲーム開始時にどのデッキを混ぜるかを選ぶ。`data/decks/*.json` を1ファイル1デッキとして置く。

| デッキ | ファイル | rating | 5音 | 7音 | 内容 |
|---|---|---|---:|---:|---|
| 標準 | `standard.json` | all | 108 | 141 | 仕事・家庭・恋愛・日常・自然の平凡な語彙 |
| ネットミーム・流行語 | `meme.json` | all | 118 | 107 | SNS・オタク・ソシャゲ・時事（うち慣用句35枚） |
| 下ネタ（大人向け） | `spicy.json` | r18 | 87 | 135 | 身体・行為・夜の街・修羅場・加齢 |

計 696枚。

**標準デッキの平凡さは意図的**。このゲームの笑いは札単体ではなく落差から出るので、「春の風／炎上しても／給料日」「朝五時に／据え膳を食う／冷蔵庫」のように、真面目な札とふざけた札が同じ手札に来る状態を作る必要がある。全部の札が面白いと、かえって何も面白くならない。

#### デッキ選択のルール

- 標準デッキは常時オン（オフにできない）。山札の骨格になるため。
- `meme` はデフォルトでオン。
- `rating: "r18"` のデッキは**デフォルトでオフ**。設定画面で明示的にオンにしたときだけ山札に混ざる。プレイヤー登録画面に「大人向けの札を含みます」の確認を1回出す。
- 山札は選択されたデッキの札を全部混ぜて作る。5音山・7音山は別々。

### 3.4 検証

`node scripts/validate-cards.mjs` で全デッキを横断チェックする。

- `reading` から数えたモーラ数が `mora` の宣言値と一致するか
- IDの重複（デッキをまたいでも禁止）
- **読みの重複**（デッキをまたいでも禁止。同じ読みの札が2枚あると「山札には各札1枚ずつ」の前提が崩れるため）
- `reading` がひらがな＋長音符のみで書かれているか
- **5音札が助詞で終わっていないか**（3.2.1のルール。`を` `が` `は` `へ` `より` `まで` `から` `には` `では` `でも` `にも` などを末尾で検出する）

助詞チェックについて補足すると、`と` `に` `で` `も` は名詞の末尾にもよく現れるため（「過去の人」「潮の跡」「事後の朝」）判定から外している。逆に「エロ動画」「貧乳派」のように `が` `は` で終わる正当な名詞はスクリプト内の `NOUN_EXCEPTIONS` に読みを登録して通す。

札を追加・編集したら必ず通す。

## 4. 共通のゲームフロー

```
[ゲーム開始]
  ↓ モード選択・プレイヤー登録（名前入力）
  ↓ 山札をシャッフル、全員に 5音札4枚 + 7音札2枚 を配る
  ↓
[ラウンド 1..N]  ※ N = プレイヤー人数（全員が1周）
  ↓ 役割決定（親 or 提出者を順番に回す）
  ↓ 交換フェーズ（最大2回）
  ↓ 作句・提出フェーズ
  ↓ 判定フェーズ（モードにより異なる）
  ↓ 結果表示 / ポイント加算
  ↓ 手札補充（使った分だけ引く）
  ↓
[全ラウンド終了] → 総合結果画面
```

### 4.1 手札の補充

句に使った3枚（5音2枚 + 7音1枚）だけを山札から引いて補充する。**使わなかった札は手元に残る**ので、良い札を温存する戦略が生まれる。

### 4.2 山札が尽きたとき

捨て場の札をシャッフルして山札に戻す。捨て場は空になる。5音山・7音山それぞれ独立に判定する。

---

## 5. モードA: 独断と偏見モード

親の主観だけで勝敗が決まるモード。

### フロー

1. **親を決める** — 1ラウンドごとに時計回りで交代。全員が1回ずつ親をやる。
2. **親はお題を出さない** — テーマなし。純粋に「一番良かった句」を親の好みで選ぶ。
3. **親以外の全員**が交換フェーズを経て句を提出する。
4. 全員の提出が終わったら**全員に全句を公開**する（誰の句かは伏せる＝匿名表示）。
5. **親が1句を選ぶ。** 選ばれた句の作者に **1ポイント**。
6. 選ばれた後に作者を公開する。

### 補足
- 親は句を作らない。待ち時間中は他プレイヤーの提出状況が見える。
- 匿名表示は「誰の句か分からないほうが公平に選べる」ため。設定でオフにできる。

---

## 6. モードB: コンテストモード

100点満点で採点し合うモード。

### フロー

1. **提出者を決める** — 1ラウンドごとに交代。全員が1回ずつ提出者をやる。
2. **提出者だけ**が交換フェーズを経て句を提出する。
3. 提出された句を**全員に公開**する（作者は自明なので記名）。
4. **提出者以外の全員**が 0〜100点で採点する。他人の点数は見えない状態で入力する。
5. 全員の入力が終わったら一斉公開。**その句の得点 = 採点の平均点**。
6. 平均点をそのプレイヤーのスコアとして記録する。

### 勝敗
全員が1周した時点で、**平均点が最も高かったプレイヤーの勝ち**。

### 補足
- 提出者は自分に点を入れられない。
- 採点者の人数は常に「プレイヤー数 - 1」なので、平均点は全員公平に比較できる。
- 誰が何点を付けたかは公開する（盛り上がるので）。設定で匿名にもできる。

---

## 7. 交換フェーズと捨て場

両モード共通のルール。

- 交換は **1ラウンドにつき最大2回**。ラウンドが変わるとリセットされる。
- 1回の交換で**何枚でも**出してよい（1枚〜手札全部）。出した枚数と同じ枚数を引く。
- 引く先は **山札 or 捨て場** を1枚ずつ選べる。
- 5音札を出したら5音札を、7音札を出したら7音札を引く（枚数構成 4 + 2 は常に維持される）。

### 捨て場

- 交換で出した札は**表向きで捨て場に置かれ、全プレイヤーに見える**。
- 誰が何を捨てたかも表示する（読み合いの材料になる）。
- 他プレイヤーは自分の交換タイミングで、山札の代わりに捨て場から札を拾ってよい。**早い者勝ち**。
- 捨て場に置かれた札はラウンドをまたいで残る（山札が尽きたときのみ回収）。

---

## 7.1 制限時間

| 区間 | 既定 | 対象フェーズ |
|---|---:|---|
| 交換〜作句 | 5分 | `turn` |
| 審査・採点 | 2分 | `judge` / `rate` |

**引き継ぎ画面（`handoff`）は計らない。** 端末を物理的に渡す時間なので、ここに制限をかけると理不尽になる。

時計は交換と作句をまたいで通しで動く。交換に4分使えば作句は1分しか残らない、という配分もプレイヤーの判断に委ねる。

### 時間切れの処理

進行が止まらないよう、`TIMEOUT` アクションでその場を自動的に解決する。

| フェーズ | 時間切れの結果 |
|---|---|
| 交換・作句 | 自動提出。**選びかけの札はそのまま活かし、空いている位置だけ手札から補う** |
| 審査 | 画面に出ている並びの先頭の句が選ばれる |
| 採点 | 50点（中央値）が入る |

自動提出で選択を捨てないのは、「上句だけ決めて悩んでいたら切れた」ときに全部他人任せの句が出てくると納得感がないため。この判定はUIではなくエンジン側（`reducer.ts`）に置いてあるので、オンライン版でもサーバーが同じ処理をそのまま使える。

`timeLimits` を `null` にすれば無制限になる。

## 8. データモデル（案）

```ts
type Card = {
  id: string;
  deck: 'standard' | 'meme' | 'spicy';
  mora: 5 | 7;
  text: string;
  reading: string;
  idiom?: boolean;   // 「知らんけど」など、述語形だが下句にも置ける決まり文句
  tags: string[];
};

type GameSettings = {
  decks: Card['deck'][];   // 標準は常に含む。spicy はユーザーが明示的に有効化したときのみ
  exchangeLimit: number;   // デフォルト2（ラウンドごと）
  anonymousSubmission: boolean; // 独断と偏見モードの匿名表示。デフォルト true
  revealRaters: boolean;   // コンテストモードで誰が何点付けたか公開。デフォルト true
  timeLimits: { turn: number | null; judge: number | null };  // 秒。null で無制限
  passAndPlay: boolean;    // false ならオンライン（引き継ぎ画面なし・同時進行）
};

type Player = {
  id: string;
  name: string;
  hand: Card[];          // 5音4枚 + 7音2枚
  score: number;         // 独断と偏見: 勝ち数 / コンテスト: 平均点の合計
  scoreHistory: number[];
};

type Haiku = {
  authorId: string;
  upper: Card;   // 5音
  middle: Card;  // 7音
  lower: Card;   // 5音
};

type GameState = {
  mode: 'dokudan' | 'contest';
  settings: GameSettings;
  players: Player[];
  deck5: Card[];
  deck7: Card[];
  discardPile: { card: Card; discardedBy: string }[];
  round: number;              // 0-indexed
  activeIndex: number;        // 親 or 提出者
  turnQueue: string[];        // このフェーズでまだ行動していない人
  pendingPhase: Phase | null; // 引き継ぎ画面の先で始まるフェーズ
  seed: number;               // 山札のシャッフルと表示順に使う。配信時は落とす
  // 交換と作句は turn ひとつにまとめてある。オンラインでは各自が自分のペースで
  // 行き来するので、全体で「交換フェーズ」「作句フェーズ」と区切れないため
  phase: 'setup' | 'handoff' | 'turn' | 'judge' | 'rate' | 'roundResult' | 'gameover';
  exchangesUsed: Record<string, number>; // playerId -> 0..2（ラウンドごとにリセット）
  submissions: Haiku[];
  ratings: Record<string, number>;       // コンテスト用 raterId -> 0..100
};
```

ゲームロジックは **純粋な reducer**（`(state, action) => state`）として UI からも通信からも切り離してある。1台版はブラウザの中で、オンライン版はサーバーの中で、同じ reducer が回る。

プレイヤーの行動を表すアクションには必ず `playerId` を付ける。オンラインでは複数人が同時に動くので、「いま手番の人」を状態から一意に決められないため。サーバーは受け取った `playerId` を信用せず、接続に紐づいた席で上書きしてから reducer に渡す。

## 10. 技術選定（実装済み）

パス&プレイ版は実装済み。`npm run dev` で動く。エンジン（`src/engine/`）にテスト17件。


| 項目 | 選択 | 理由 |
|---|---|---|
| 言語 | TypeScript | 後のオンライン化でクライアント・サーバー間の型共有ができる |
| UI | React + Vite | 軽量。スマホブラウザでそのまま動く |
| 状態管理 | 自前 reducer（`src/engine/`） | UIと完全分離。サーバーへ移植可能 |
| 永続化 | localStorage | 中断・再開に対応 |
| 配信 | 静的サイト（PWA化も可） | インストール不要でスマホ1台で遊べる |

### オンライン対戦（実装済み・PCブラウザ想定）

`ranking-tote` と同じ構成を踏襲した。Express + Socket.IO、サーバー権威の状態管理、部屋コードをURLに載せて招待状兼用、`sessionStorage` でタブごとの再接続、Render へのデプロイ。

| 項目 | 内容 |
|---|---|
| 部屋コード | `ふゆのあさ-おおかみ-913` のような語呂のよいスラッグ。URL `/r/<code>` が招待状 |
| 参加 | 先着8人。3人から開始できる。ホストは最初に部屋を作った人 |
| 再接続 | `sessionStorage` に席を保存。リロードで元の席に戻る。localStorage を使うと同じブラウザの2つ目のタブが1つ目の席を奪うので使わない |
| 切断 | 開始前ならロビーから消す。開始後は席を残し、時間切れで自動処理させる |
| 権限 | モード・デッキの設定と「次のラウンドへ」はホストのみ。クライアントが名乗る playerId は信用せず、接続に紐づいた席で上書きする |
| 時計 | サーバーが持つ。クライアントは締切時刻を受け取って描くだけ |
| 部屋の寿命 | 誰も繋いでいない部屋は6時間で掃除する |

#### 配信内容の絞り込み

全員に同じ状態を送らず、`viewFor(state, playerId)` で1人分に絞ってから送る。通信を覗かれても破綻しないことを基準にした。

| 落とすもの | 理由 |
|---|---|
| 他人の手札 | 見えたら勝負にならない |
| 山札の中身 | 次に何が来るか分かってしまう |
| 乱数シード | 山札を落としても、シードがあれば引く順番を計算できる |
| 提出前の他人の句 | 先に読んで寄せられる |
| 審査中の作者ID | 匿名審査が成立しなくなる。親は表示順の位置で選ぶ |
| 採点中の他人の点 | 引きずられる。自分の点だけ残す |

### 変更点（1台版との差）

1. **引き継ぎ画面が出ない。** `settings.passAndPlay` が false のとき `handoff` を挟まず直接フェーズに入る。
2. **`turnQueue` が「待ち行列」ではなく「まだ提出していない人」になる。** 独断と偏見モードは全員が同時に作句できるので、順番待ちが消えて所要時間が大幅に縮む。提出の順番は前後してよい。コンテストモードは1人ずつ出す仕様なので、他の人は待つか、次の自分の番に備える時間になる。
3. **ラウンドを進めるのはホストだけ。** 1台版では誰でも押せる「次のラウンドへ」が、オンラインではホスト専用になる。
