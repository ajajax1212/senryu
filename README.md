# 五七五 — 川柳ゲーム

配られた札を組み合わせて五・七・五の川柳を作り、人間の主観だけで勝敗を決めるパーティーゲーム。
端末を1台まわして遊ぶ（パス&プレイ）。

遊び方は2通り。

- **オンライン対戦（PCブラウザ想定）** — 部屋を作ってURLを配る。各自が自分の画面で手札を見るので、独断と偏見モードは**全員が同時に作句できる**。
- **1台をまわす（パス&プレイ）** — スマホ1台を手渡しで回す。手番のたびに手札を隠す仕切りを挟む。

## 動かす

```bash
npm.cmd install
npm.cmd run build
npm.cmd start
```

`http://localhost:3300` を開く。`PORT` 環境変数で変更できる。

| コマンド | 内容 |
|---|---|
| `npm.cmd start` | サーバー（オンライン対戦つき、`dist/` を配信） |
| `npm.cmd run build` | クライアントとサーバーをビルド |
| `npm.cmd run dev` | クライアントだけの開発サーバー。1台版の確認用 |
| `npm.cmd run dev:server` | サーバーだけを watch 起動 |
| `npm.cmd test` | エンジンのテスト（39件） |
| `npm.cmd run validate` | 札データの検証 |

## デプロイ

`render.yaml` を同梱してある。Render に接続すればそのまま Web Service として動く（`npm install && npm run build` → `npm start`）。部屋の状態はサーバーのメモリに持つので、インスタンスが落ちると進行中のゲームは消える。

### Windows PowerShell で `npm` が動かない場合

```
npm : このシステムではスクリプトの実行が無効になっているため、
ファイル C:\Program Files\nodejs\npm.ps1 を読み込むことができません。
```

PowerShell の実行ポリシーが `npm.ps1`（インターネット由来のマークが付いた署名なしスクリプト）をブロックしている。**`npm` の代わりに `npm.cmd` と打てば回避できる。** バッチファイルなので PowerShell のスクリプト実行ポリシーを通らない。

毎回打ち分けたくなければ、どちらかを自分で実行する（どちらもセキュリティ設定の変更になるので、内容を確認してから）。

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

現在のユーザーだけ、ローカル作成のスクリプトと署名済みスクリプトを許可する。一般的な開発環境の設定。あるいは npm のファイルだけマークを外す方法もある。

```powershell
Unblock-File "C:\Program Files\nodejs\npm.ps1", "C:\Program Files\nodejs\npx.ps1"
```

影響範囲は狭いが、管理者権限が要る。

## 設計

**エンジンは同じものをブラウザとサーバーの両方で動かしている。** `reducer.ts` は純粋な `(state, action) => state` で、1台版はブラウザの中で、オンライン版はサーバーの中で回る。ルールが二重に実装されている箇所はない。

3つだけ、オンラインのために入れてある仕掛けがある。

1. **`settings.passAndPlay`** — false なら引き継ぎ画面を出さず、`turnQueue` に入っている全員が同時に行動できる。true なら先頭の1人だけ。フェーズの遷移はどちらも同じコードを通る。
2. **`view.ts` の `viewFor(state, playerId)`** — サーバーは全員に同じ状態を送るのではなく、1人ずつ中身を絞って送る。他人の手札を空にするだけでなく、山札の中身と乱数シードも落とす。シードが漏れると次に何を引くか計算できてしまうため。審査中は句から作者IDを外し、親は「表示順の何番目か」で選ぶ。
3. **時計はサーバーが持つ** — クライアント側のタイマーに任せると、そのブラウザが閉じられた瞬間に進行が止まって誰も先に進めなくなる。クライアントは締切時刻を受け取って残り時間を描くだけ。

## 制限時間

交換〜作句が5分、審査・採点が2分。引き継ぎ画面は計らない。時間切れになると自動で進むが、作句中なら**選びかけの札は活かして空いた位置だけ補う**。詳細は [SPEC.md](docs/SPEC.md) の 7.1。

## 札を書くときのルール

- **5音札は名詞か名詞句にする。** 上の句にも下の句にも置けないといけないので、助詞で終わると下句に回せなくなる。○「上司の目」×「上司の目が」
- **例外として慣用句は5音札に置ける。** 「知らんけど」「草生える」「ととのった」のように、語形は述語でも一語の決まり文句として機能する札は体言止めの位置でも句が閉じる。データ上は `"idiom": true` を立てて品詞チェックを免除する。
- **7音札（中の句）は述語句でよい。** むしろ「〜して」「〜だった」の形が上下をつなぐので望ましい。
- 音数は文字数ではなくモーラ数。拗音（ゃゅょ等）は直前のかなと合わせて1、促音「っ」・撥音「ん」・長音「ー」は1と数える。「残業日（ざんぎょうび）」は6文字だが5モーラ。

## 札データの検証

札を追加・編集したら必ず実行する。

```bash
npm run validate
```

`reading`（ひらがな読み）から数えたモーラ数が `mora` と一致するか、5音札が助詞で終わっていないか、IDと読みが重複していないか（デッキをまたいでも）を検証する。

## デッキを足す

`data/decks/` に同じ形式のJSONを置けば自動的に山札にも検証対象にも入る。IDのプレフィックスは既存と衝突しないものを使う（standard=`m`, meme=`n`, spicy=`s`）。

```jsonc
{
  "deck": "myDeck",
  "label": "自作デッキ",
  "rating": "all",        // "all" | "r18"（r18はデフォルトOFF）
  "cards": [
    { "id": "x5-001", "mora": 5, "text": "残業日", "reading": "ざんぎょうび", "tags": ["仕事"] },
    { "id": "x5-002", "mora": 5, "idiom": true, "text": "知らんけど", "reading": "しらんけど", "tags": ["口語"] }
  ]
}
```
